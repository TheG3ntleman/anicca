You are performing phase 2 only.

Critical output rules:
1. Return exactly one JSON object and nothing else.
2. Do not output explanations, planning, self-corrections, or commentary.
3. Always return all top-level keys: `candidate_records`, `candidate_artifacts`, `uncertainties`.
4. If a list is empty, return `[]`.
5. Use record IDs `r1`, `r2`, `r3`, ... in source order.
6. Use artifact IDs `a1`, `a2`, `a3`, ... in source order.
7. IDs must be unique across all phase-2 candidates.
8. `notes` must be short, factual, and neutral. Do not write notes like `need to fix this`, `let's`, `I'll`, `maybe`, or `alternatively`.
9. Each item in `uncertainties` must be a plain string, not an object.

You will be given a journal entry.

Your task is to extract candidate records and candidate artifacts directly supported by the text.

Definitions:
- A candidate record is a text span describing the journal author's thought, emotion, behaviour, or body state.
- A candidate artifact is an identity-worthy object or encounter directly supported by the text.

Allowed process_type values:
- thought
- emotion
- behaviour
- body

Process typing reminders:
- `thought`: beliefs, appraisals, judgments, desire, uncertainty statements, rumination, rehearsal, internal deliberation, interpretation
- `emotion`: explicitly felt emotional states
- `behaviour`: actions, speech acts, outward conduct, bodily actions
- `body`: directly described bodily states or physical sensations

Record rules:
1. Extract only the journal author's processes.
2. Do not extract other people's actions, speech, or emotions as candidate_records.
3. Preserve negation exactly.
4. Do not treat a pure object span as a candidate_record.
5. Do not use `body` as a fallback for vague internal experience.
6. Split mixed clauses when the resulting parts can each stand alone clearly.
7. If a clause contains both a bodily state and another process, split them when possible.
8. If a clause contains both a thought and an emotion, split them when possible.
9. If a clause contains separate actions joined by `and`, `then`, or a scene shift, do not combine them if they can stand alone.
10. If a speech act and its content appear in one clause, prefer the speech act as a `behaviour` record unless the content also stands alone clearly.
11. Each candidate_record must have exactly one `source_text`.
12. Use the smallest exact contiguous span that can stand on its own.

Allowed artifact_kind values:
- object
- encounter

Artifact rules:
1. Use `object` for identity-worthy non-event things such as people, places, roles, documents, messages, projects, or recurring non-event items.
2. Use `encounter` for substantial event-like episodes such as conversations, calls, meetings, dinners, rides, appointments, consultations, scans, procedures, trips, arguments, incidents, or past events.
3. Past events and procedures usually belong in `encounter`, not `object`.
4. Exclude low-value incidental objects unless they seem central.
5. Object artifacts must have exactly one `source_text`.
6. Encounter artifacts may have one or more `source_texts`.
7. For every substantial event-like episode, create at least one encounter artifact.
8. Do not create one giant encounter for the whole entry.
9. If time, location, participants, or scene clearly shift, use separate encounter artifacts.
10. Encounter `source_texts` should stay local to one coherent episode.

General rules:
1. Be high recall.
2. Use exact contiguous text from the entry.
3. Do not paraphrase.
4. Output items in source order.
5. Overlap is allowed.
6. Do not deduplicate.
7. Do not create references between items.
8. Do not infer hidden meaning, diagnosis, symbolism, or deeper causes.

If something is genuinely unclear, record that in `uncertainties` instead of reasoning out loud in `notes`.

Return JSON in exactly this shape:

{
  "candidate_records": [
